# SimplifyKit 0.11.0

Bản này gộp mọi thay đổi từ 0.5.0 tới 0.11.0. Các bản giữa chưa từng được release riêng.

## Có gì mới

- **Lệnh mới `/sk:ff`** (0.6.0) dành cho item nhỏ. Lệnh này viết mọi artifact còn thiếu trong một lần: spec delta, rồi design hoặc ghi chú Skipped, rồi tasks. Xong thì nó dừng để bạn duyệt cả ba cùng lúc.

  ```
  /sk:ff us-12345-<tên-ngắn>
  ```

  - Chỉ chạy khi **bạn gõ** lệnh. Model không tự chọn nó, nên câu "làm hết các bước còn lại" vẫn đi qua `/sk:continue` và chỉ ra một artifact.
  - Nó dừng sớm ngay sau spec delta nếu delta có `## MODIFIED Requirements` hoặc phát sinh Gap.

- **`/sk:apply` viết test trước** (0.8.0). Mỗi `#### Scenario` có một test viết từ chính scenario đó, phải thấy đỏ đúng lý do rồi mới viết code, và thấy xanh sau khi code xong.
  - Không có shell thì test vẫn được viết nhưng không chạy, và close-out nói rõ là chưa chạy.
  - Repo chưa có test setup thì nó không tự cài framework; nó hỏi bạn một lần.

- **`design.md` có mục `## Contracts`** (0.8.0). Change thêm hoặc đổi public interface (exported function, endpoint, props, CLI, event, DB schema) thì interface được ghi ở đây đúng như sẽ code, để bạn duyệt trước khi có dòng code nào.
  - `/sk:apply` code và test bám đúng contract; cần signature khác thì nó dừng lại hỏi.
  - `/sk:verify` báo CRITICAL nếu code lệch contract.

- **Bug và Test Case trên Azure DevOps** (0.9.0):
  - Với Bug, `/sk:propose` lấy **expected result trong Repro Steps** làm AC, nên Bug có ghi rõ kết quả mong đợi không còn rơi vào "thiếu AC".
    - Change-id có dạng `bug-<id>-<tên-ngắn>`.
    - Các bước được chép vào `## Repro steps`, actual result vào dòng `**Symptom:**`.
    - Repro không có expected result thì nó hỏi bạn chứ không đoán.
    - Nếu `sk/specs/` đã có scenario nói đúng expected result đó, nó không tạo change nào và chỉ ra scenario để bạn sửa bằng commit kèm `AB#<id>`.
  - Với change từ Bug, `/sk:apply` phải thấy test đầu tiên đỏ **đúng với triệu chứng** trước khi sửa. Test xanh ngay nghĩa là chưa tái hiện được lỗi.
  - **Test case** liên kết qua *Tested By* được đọc với mọi loại work item, tối đa 10. Từng bước được ghi vào `## Test cases`, kèm nhãn `covered`, `pins`, `open` hoặc `confirmed as criterion`.
    - Test case là bằng chứng, không phải AC.
    - Expected result mà AC không nhắc tới, hoặc mâu thuẫn với AC, thành câu hỏi cho bạn, không tự lọt vào spec.

- **Lệnh mới `/sk:pr`** (0.10.0) soạn mô tả PR từ các artifact của change, đọc được cả change đã archive.

  ```
  /sk:pr us-12345-<tên-ngắn>
  ```

  - Nội dung gồm `AB#`, requirement được thêm / sửa (sửa gì) / bỏ, contract, tiến độ task, những gì còn mở trước khi merge, mục Evidence để bạn tự điền, và mức rủi ro khi merge (one-way hay two-way door, ai bị ảnh hưởng).
  - Nó không tạo PR, không ghi file nào.

- **Mục `## Out of scope` trong `proposal.md`** (0.11.0) ghi những gì change **cố ý không làm**, kèm nguồn: comment, chữ trong AC, câu bạn trả lời, hoặc test case bị loại.
  - Chỉ ghi thứ có nguồn loại trừ thật.
  - `/sk:continue` không viết scenario cho các mục này, `/sk:apply` dừng lại hỏi nếu một task đòi làm, `/sk:verify` chỉ ra nếu code lại làm, và `/sk:pr` liệt kê chúng.

- **Lệnh mới `/sk:questions`** (0.11.0) gom Gaps, Open questions và các assumption chưa xác nhận thành `sk/changes/<id>/questions.md`, viết cho PO/BA đọc được.

  ```
  /sk:questions us-12345-<tên-ngắn>
  ```

  - Mỗi câu có nguồn, các lựa chọn và đáp án đề xuất.
  - Câu trả lời không đi qua file này: PO trả lời bằng comment trên work item, rồi bạn chạy lại `/sk:propose`.

- **Git hook `pre-push`** (0.7.0, tuỳ chọn). Hook này chặn push khi một change đã tick hết task mà chưa `/sk:archive`, hoặc khi `sk/specs/` còn dấu `[[OPEN:Q<n>]]`.
  - `/sk:init` chỉ đề nghị cài khi có Bash và bạn đồng ý.
  - Muốn push bất chấp một lần thì dùng `git push --no-verify`.

- **Hỏi qua hộp chọn** (0.5.0). `/sk:propose`, `/sk:archive` và `/sk:init` hỏi qua `AskUserQuestion` của Claude Code khi có, với đáp án đề xuất đứng đầu. Không có tool đó thì vẫn hỏi bằng text như trước.

- **Plugin tuỳ chọn `sk-status`** (0.1.1). Plugin này hiện status line, gợi ý lệnh tiếp theo khi bấm Tab, và bảng `/sk-status` cho từng change. Nó chỉ đọc. `sk` vẫn chạy y nguyên dù không cài nó:

  ```
  /plugin install sk-status@simplify
  ```

## Nâng cấp từ 0.4.x

`claude plugin update sk@simplify`, rồi mở session Claude Code mới. Các lệnh mới được tìm thấy qua description của chúng.

Workspace hiện có dùng được nguyên trạng. Chạy lại `/sk:init` chỉ cần khi bạn muốn cài hook `pre-push`, mỗi clone một lần, vì git không clone thư mục hook. Lệnh này không sửa danh sách lệnh đã ghi trong `CLAUDE.md` của repo. Muốn nhắc tới `/sk:ff`, `/sk:pr` hay `/sk:questions` ở đó thì bạn tự thêm.

Change đang làm dở không cần sửa gì:
- Proposal cũ không có `## Repro steps`, `## Test cases` hay `## Out of scope` thì các lệnh coi như mục đó trống.
- Change đã có design từ trước mà không có `## Contracts` thì cứ để vậy.
