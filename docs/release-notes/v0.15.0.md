# SimplifyKit 0.15.0

Từ bản này, một lệnh `/sk:verify` dùng được cho cả hai lần review: tác giả tự review trước khi Publish, và dev khác review PR. `verify` vẫn không ghi file nào.

## Có gì thay đổi

- **Chiều thứ tư: Code health.** Ba chiều Completeness, Correctness và Coherence kiểm những gì change đã hứa. Code health kiểm lỗi trong chính code mà spec không nhắc tới: logic sai, lỗi bị nuốt, null/biên, đồng thời, credential lọt ra log, thiếu kiểm quyền.
  - Có tool `Agent` thì Code health chạy trong một subagent chỉ được xem diff, file tiêu chuẩn và `sensitive:`, không xem spec. Nhờ vậy nó đọc code thực sự làm gì, chứ không phải code định làm gì.
  - Mỗi phát hiện ghi `file:dòng` kèm bằng chứng đọc từ code. CRITICAL chỉ khi có bằng chứng cụ thể (lỗ hổng, mất dữ liệu, crash có đường tái hiện). Lỗi có từ trước diff mang nhãn `pre-existing`, tối đa SUGGESTION.
  - Kết quả nằm trong mục `### Code health` riêng, dùng chung dãy mã `V<n>` với phần còn lại của báo cáo.

- **Các vòng review hội tụ.**
  - Từ vòng 3, `verify` chỉ tìm vấn đề mới trong phần diff kể từ vòng trước; vấn đề cũ còn mở chỉ được cập nhật trạng thái.
  - Từ vòng 4, dòng kết đề nghị xem lại cách tiếp cận thay vì sửa tiếp.
  - Diff chạm vùng `sensitive:` thì dòng kết nhắc chạy `/security-review`.

- **Review PR của người khác: `/sk:verify --pr <id>`.**
  - Đọc PR và các thread qua REST, chỉ đọc. Không tự chạy `git fetch` hay `git worktree add`: lần đầu nó in đúng các lệnh để bạn chạy, rồi bạn gọi `/sk:verify --pr <id> <đường-dẫn>`.
  - Change thường đã archive trước khi Publish, nên `verify` lấy các requirement mà PR thêm/sửa trong `sk/specs/` làm chuẩn.
  - `sk/config.yaml` lấy từ nhánh đích, không phải từ PR. PR có sửa config hay script test thì nó hỏi trước khi chạy test.
  - Chi tiết: `plugins/sk/reference/pr-review.md`.

- **Verify cả change đã archive**, để tác giả chạy tiếp các vòng sửa sau khi archive. **Không có change nào** (PR refactor, sửa nóng): `verify` chỉ chạy Code health và test, ba chiều còn lại ghi vào mục *Skipped*.

- **Eval:** thêm 3 case, đều đạt 1.00. Riêng `--pr` và giới hạn vòng cần shell nên chỉ kiểm được bằng tay.
